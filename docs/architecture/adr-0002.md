# ADR-0002 — Move to a new Supabase instance, cold start

## Status

Accepted. Decided 2026-09-20.

## Context

The previous project database lived on an old Supabase project whose schema had
drifted from any reproducible definition. Payloads (students, seasons, submissions)
are re-importable from the roster sheet, so there was no real data continuity at
stake — only accumulated schema debt.

## Decision

Provision a brand-new Supabase instance (Ref `sfcqhkbynjxcksogcnwa`, region
ap-south-1) and start cold: nothing from the old project is carried over. The schema
is built up exclusively by the first tracked Prisma migration rather than reverse
engineering whatever state the old project happened to be in.

## Consequences

- Clean migration history from day one; the new instance's schema matches the
  repository exactly and is reproducible from it.
- No data was migrated, so the roster import is the mandatory first step on any
  fresh environment.
- Old project credentials and schema become irrelevant; only the new `DATABASE_URL`
  (`postgresql://postgres.sfcqhkbynjxcksogcnwa:<pw>@aws-0-ap-south-1.pooler.supabase.com:5432/postgres`)
  is used, password kept out of the repo.
