# ADR-0004 — Keep three separate buildables; no monorepo

## Status

Accepted. Decided 2026-09-20.

## Context

The portal is three deployable units that share very little code: `web` (Vite+React
student portal), `admin-client` (Vite+React admin UI), and `backend` (Express+Prisma
API + admin static serving). The project
has a sole or rotating maintainer, is edited heavily with AI assistance, and must be
handed off primarily through documentation. A monorepo toolchain (Turbo, Nx) would
be one more system to learn and keep healthy for an organization that is this small.

## Decision

Keep three separate buildables in one git repository with no monorepo orchestration.
No Turbo/Nx consolidation is adopted; each project keeps its own config, package
manifest, and build.

## Consequences

- Configuration (lint, TS, build, env) is duplicated across projects; changes must
  sometimes be made in more than one place.
- In exchange, local setups stay simple — each buildable can be run and understood
  on its own, which lowers the onboarding surface for a rotating maintainer.
- Fewer moving parts for AI-assisted edits: no workspace graphs or task pipelines
  to keep consistent with reality.
